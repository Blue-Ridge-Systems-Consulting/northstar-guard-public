# Blue Ridge Repository Branding

This repository follows the Blue Ridge Systems Consulting documentation standard.

## Standard assets

| Asset | Path | Use |
|---|---|---|
| Blue Ridge standard logo | `assets/blue-ridge-systems-consulting-logo.svg` | Centered at the top of the README and used for repository identity |
| Blue Ridge square favicon | `assets/favicon.svg` | Browser favicon for any static page generated from this repository |
| Aikido Security logo | `assets/aikido-security-logo.svg` | Centered security footer at the bottom of the README |

## README layout standard

1. Blue Ridge Systems Consulting logo centered at the top.
2. Existing repository title and documentation preserved.
3. Aikido Security logo centered at the bottom.

## Color standard

| Role | Hex |
|---|---|
| Deep navy | `#08111f` |
| Infrastructure blue | `#0b2342` |
| Ridge cyan | `#38bdf8` |
| Electric cyan | `#22d3ee` |
| Success green | `#9be870` |
| Light text | `#f8fafc` |

## Writing standard

Use plain operational language. Keep the tone direct, practical, and security-aware. Preserve existing technical documentation when applying branding.

## Security standard

Never commit secrets, tokens, credentials, private keys, certificates, state files, `.env` files, databases, backups, or real production configuration values.

Security posture should be visible, but credentials should stay invisible.
